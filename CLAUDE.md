# CLAUDE.md — ulsportugal

## Project overview

**ulsportugal** is an R package that provides ready-to-use `sf` geometries for the 39 *Unidades Locais de Saúde* (ULS) of mainland Portugal (*Portugal Continental*). It automates the aggregation of official geometries at the *freguesia* and *concelho* levels, normalises territorial names and codes (DICO/LAU), and harmonises data between Eurostat (via `giscoR`) and national reference sources (DGT / CAOP).

The package is authored by Daniel Rodrigues and released under the MIT licence.

## Exported functions

### `ulsportugal(ano = "2021", verbose = FALSE)`

Returns an `sf` object (POLYGON/MULTIPOLYGON) with one row per ULS.

Output columns:

| Column       | Description                                                  |
|--------------|--------------------------------------------------------------|
| `NOME_ULS`   | Full official name of the ULS                                |
| `NOME_CURTO` | Short label (e.g. `"S. João"`, `"Coimbra"`) for map legends |
| `geometry`   | Aggregated geometry for the ULS territory                    |

How it works:
1. Fetches LAU geometries for Portugal from `giscoR::gisco_get_lau()` for the given `ano`.
2. Extracts the 4-digit DICO code from the LAU identifier and filters to mainland districts (`DIST < 20`).
3. Joins against the internal `dicionario_mestre` lookup — first by exact DICO + *Freguesia* name, then by DICO alone (for concelhos with a single ULS).
4. Unions geometries by `NOME_ULS` and derives `NOME_CURTO` by stripping the standard prefix/suffix.
5. Warns if the result does not have exactly 39 rows.

---

### `juntar_uls(dados, col_freguesia = "Freguesia", col_dico = NULL)`

Takes a user's `data.frame` with data at the *freguesia* level and returns the same data frame with `NOME_ULS` and `NOME_CURTO` columns added. Does **not** add geometry or aggregate rows.

Join strategy (in priority order):
1. **DICO + Freguesia name** — most reliable; requires `col_dico`.
2. **DICO only** — used as fallback for concelhos with a single ULS.
3. **Freguesia name only** — used when `col_dico = NULL`; more fragile, emits a message.

Rows without a ULS match are kept with `NOME_ULS = NA` and a warning is emitted.

---

### `agregar_por_uls(dados, col_freguesia = "Freguesia", col_dico = NULL, fn = sum, geometry = TRUE, ano = "2021", verbose = FALSE)`

Takes a user's `data.frame` at the *freguesia* level, aggregates all numeric columns to the ULS level using `fn` (default `sum`), and optionally joins the ULS geometries via `ulsportugal()`.

Returns an `sf` object when `geometry = TRUE` (default), or a plain `tibble` when `geometry = FALSE`.

Typical usage:

```r
mapa <- agregar_por_uls(dados_freguesias, col_dico = "DICO")
ggplot(mapa) + geom_sf(aes(fill = casos))
```

## Internal data (`dicionario_mestre`)

The master dictionary is built from `inst/extdata/dicionario_uls.csv` and saved to `R/sysdata.rda` via a data-prep script (not committed in the package itself). Key columns:

- `DICO` — 4-digit territorial code (*Divisão Interna de Codificação*)
- `Freguesia` — *Freguesia* name as returned by `giscoR` (NA for concelho-level entries)
- `NOME_ULS` — Target ULS name

When updating the dictionary (e.g. after a ULS boundary change), edit the CSV and re-generate `sysdata.rda`.

## Language and naming conventions

- Package language is **Portuguese (pt-PT)**.
- Function and column names are in **Portuguese**.
- Code comments and documentation (`@title`, `@description`, `@param`, etc.) should also be in Portuguese.
- Git commit messages may be in English or Portuguese.

## Common tasks for Claude

- **Add a new ULS or fix a boundary**: edit `inst/extdata/dicionario_uls.csv` and regenerate `sysdata.rda`.
- **Update documentation**: edit roxygen2 comments in `R/ulsportugal.R`, then run `devtools::document()`.
- **Debug geometry mismatches**: check whether `giscoR` changed the LAU identifier column name or format (the function already probes multiple candidate column names).
- **Add a new exported function**: create a new `.R` file in `R/`, add roxygen2 `@export` tag, run `devtools::document()`.
